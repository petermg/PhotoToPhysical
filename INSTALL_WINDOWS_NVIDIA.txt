PHOTOTOPHYSICAL
Windows + NVIDIA/CUDA installation guide
=========================================

Repository:
https://github.com/petermg/PhotoToPhysical

PhotoToPhysical is a Gradio front-end and reconstruction toolkit built around
Depth Anything 3 (DA3).

KNOWN-GOOD CORE ENVIRONMENT
---------------------------

Python:
    Python 3.10.6

Depth Anything 3:
    Repository: https://github.com/ByteDance-Seed/Depth-Anything-3.git
    Pinned commit: 3d835ec1a5802d64a8b8b15f817a1ab54809bfe4

CUDA / PyTorch stack:
    torch==2.10.0+cu128
    torchvision==0.25.0+cu128
    xformers==0.0.35

Application dependencies:
    gradio==6.25.0
    numpy==1.26.4
    open3d==0.19.0
    opencv-python==4.11.0.86
    Pillow==12.3.0
    trimesh==5.0.0

The application is intentionally configured for CUDA/NVIDIA inference.

Do not silently upgrade the pinned DA3 revision, PyTorch family, or xFormers
while troubleshooting unrelated reconstruction problems.

PREREQUISITES
-------------

1. Windows 10 or Windows 11
2. NVIDIA GPU with a compatible current driver
3. Git for Windows
4. Python 3.10.6 for the tested environment
5. Internet access for first-time model downloads

The full CUDA Toolkit is normally NOT required just to run the core DA3 app,
because the CUDA-enabled PyTorch wheel provides its runtime. A compatible
NVIDIA driver is still required.

Optional source-built CUDA extensions such as gsplat may require a CUDA
development toolkit and Visual Studio C++ Build Tools.

FRESH INSTALL - WINDOWS CMD
---------------------------

1. Clone PhotoToPhysical:

    git clone https://github.com/petermg/PhotoToPhysical.git
    cd PhotoToPhysical

2. Create the tested virtual environment:

    py -3.10 -m venv env

3. Activate it:

    env\Scripts\activate

4. Upgrade packaging tools:

    python -m pip install --upgrade pip setuptools wheel

5. Install the tested CUDA PyTorch stack:

    python -m pip install torch==2.10.0 torchvision==0.25.0 --index-url https://download.pytorch.org/whl/cu128

6. Install the matching xFormers version:

    python -m pip install xformers==0.0.35 --index-url https://download.pytorch.org/whl/cu128

7. Install the pinned DA3 revision:

    python -m pip install "depth-anything-3 @ git+https://github.com/ByteDance-Seed/Depth-Anything-3.git@3d835ec1a5802d64a8b8b15f817a1ab54809bfe4"

8. Install PhotoToPhysical direct dependencies:

    python -m pip install -r requirements-app.txt

9. Verify CUDA and imports:

    python -c "import torch; print('PyTorch:', torch.__version__); print('CUDA runtime:', torch.version.cuda); print('CUDA available:', torch.cuda.is_available()); print('GPU:', torch.cuda.get_device_name(0) if torch.cuda.is_available() else 'NONE')"

    python -c "import gradio, cv2, trimesh, open3d, xformers; from depth_anything_3.api import DepthAnything3; print('All required imports OK')"

10. Start PhotoToPhysical:

    python da3_print_gui_v2.py

The Gradio UI should open in your browser.

POWERSHELL ACTIVATION
---------------------

If using PowerShell, activate with:

    .\env\Scripts\Activate.ps1

The remaining python / pip commands are the same.

ALTERNATIVE: KEEP A LOCAL DA3 SOURCE CHECKOUT
---------------------------------------------

If you want PhotoToPhysical to run against an editable local DA3 source tree:

    git clone https://github.com/ByteDance-Seed/Depth-Anything-3.git
    cd Depth-Anything-3
    git checkout 3d835ec1a5802d64a8b8b15f817a1ab54809bfe4
    python -m pip install -e .

Use this method OR the pinned Git-URL package install above, not both unless you
understand which package path Python is importing.

MODEL DOWNLOADS
---------------

The GUI can use:

    depth-anything/DA3MONO-LARGE
    depth-anything/DA3-LARGE-1.1
    depth-anything/DA3-GIANT-1.1
    depth-anything/DA3NESTED-GIANT-LARGE-1.1

Weights are downloaded from Hugging Face on first use unless already cached.
The model weights are not stored in the PhotoToPhysical repository.

OPTIONAL NATIVE DA3 GAUSSIAN OUTPUT
-----------------------------------

Native DA3 Gaussian PLY export is available in the Multi-Image 3D workflow on:

    depth-anything/DA3-GIANT-1.1
    depth-anything/DA3NESTED-GIANT-LARGE-1.1

The Gaussian PLY itself does NOT require the optional gsplat rasterizer package.
You can enable:

    Additional DA3 outputs
      [x] Export native DA3 Gaussian Splat .ply
      [ ] Also export DA3 Gaussian preview video

and inspect the resulting PLY in a standard 3D Gaussian Splat viewer such as
SuperSplat.

OPTIONAL GAUSSIAN PREVIEW VIDEO / GSPLAT
----------------------------------------

DA3's gs_video exporter requires the pinned gsplat renderer.

Upstream DA3 pins:

    gsplat commit:
    0b4dddf04cb687367602c01196913cde6a743d70

Install from the activated PhotoToPhysical/DA3 environment with:

    python -m pip install ninja
    python -m pip install --no-build-isolation git+https://github.com/nerfstudio-project/gsplat.git@0b4dddf04cb687367602c01196913cde6a743d70

IMPORTANT:

The --no-build-isolation flag is intentional. This pinned gsplat source imports
PyTorch while preparing its compiled extension. A normal isolated pip build can
fail with:

    ModuleNotFoundError: No module named 'torch'

even when torch is correctly installed in the active PhotoToPhysical venv.

On Windows, source compilation may additionally require:

- Visual Studio C++ Build Tools / cl.exe
- a compatible CUDA development toolkit / nvcc

Do NOT randomly downgrade or replace the known-good PyTorch/CUDA stack merely to
work around a compiler/toolchain error.

If gsplat is not installed, leave "Also export DA3 Gaussian preview video" OFF.
Native Gaussian PLY export remains useful without it.

KNOWN GS_VIDEO FAILURE WHEN GSPLAT IS MISSING
---------------------------------------------

If DA3 prints:

    [WARN ] Dependency `gsplat` is required for rendering 3DGS

and the Gaussian video option is enabled, the current pinned DA3 code can later
fail with:

    NameError: name 'rasterization' is not defined

That failure is specifically the optional Gaussian VIDEO renderer. It does not
mean the Gaussian PLY format itself is unavailable.

MULTI-VIEW VIDEO INPUT SEMANTICS
--------------------------------

"Video sampling FPS" means how many source-video frames per second should be
extracted for DA3. It is not asking for the native frame rate of the video.

"Maximum views" is applied after sampling.

Examples for a 36-second clip:

    Sampling 1 FPS, Max 18 -> 18 views
    Sampling 1 FPS, Max 0  -> about 36 views
    Sampling 2 FPS, Max 0  -> about 72 views
    Sampling 30 FPS, Max 0 -> about 1080 views

Max 0 means no PhotoToPhysical view cap.

For most video experiments, start with 1-2 FPS instead of feeding every native
video frame. Hundreds or thousands of highly redundant frames can greatly
increase memory and inference time.

The 18-view default is a conservative starting point based on DA3's documented
training regime, not a hard DA3 inference limit.

CURRENT GAUSSIAN PERFORMANCE NOTE
---------------------------------

In the current PhotoToPhysical implementation, normal multi-view DA3 inference
runs first. If native Gaussian export is requested, the script performs another
DA3 inference with infer_gs=True to obtain/export the Gaussian representation.

Therefore an uncapped large video set is significantly more expensive when
Gaussian export is enabled.

OUTPUTS
-------

Generated jobs are written beneath:

TROUBLESHOOTING SNAPSHOT
------------------------

When reporting a problem, collect:

    python --version
    python -m pip freeze
    git --version
    nvidia-smi

and:

    python -c "import torch; print(torch.__version__, torch.version.cuda, torch.cuda.is_available(), torch.cuda.get_device_name(0) if torch.cuda.is_available() else None)"

The core known-good environment currently reports:

    Python 3.10.6
    PyTorch 2.10.0+cu128
    torchvision 0.25.0+cu128
    xformers 0.0.35
    CUDA available
